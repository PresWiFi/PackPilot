First public release.

## What it does
- **Import** an `.exe`, `.msi` or `.ps1`. PackPilot identifies the installer engine (MSI, Inno Setup, NSIS, WiX Burn, InstallShield, Advanced Installer and more) and fills in silent switches, name, version, publisher, MSI product code, architecture and signature.
- **Build** the `.intunewin` without IntuneWinAppUtil. The installer is wrapped in Install.ps1 / Uninstall.ps1 (silent run, 64-bit relaunch, logging to the Intune logs folder, exit code passthrough), and the package is re-opened and verified the way Intune reads it.
- **Test in Windows Sandbox:** unpacks the real package and runs detect → install → detect → uninstall → detect as SYSTEM. It learns the exact Programs and Features entry for detection and uninstall, flags App Control (Smart App Control) blocks, and can reuse one Sandbox for fast re-tests.
- **Upload to Intune (in testing)** through Microsoft Graph: Commercial / GCC, GCC High, DoD or China. Creates or updates the Win32 app and can assign it to a group, all devices or all users.
- **Deployment kit:** Intune portal values, Detect.ps1, a Deploy-ToIntune.ps1 script, and an HTML report of what was done.

## Requirements
- Windows Sandbox (Windows 10/11 Pro, Enterprise or Education) for testing.
- For uploading: an Intune role that can manage apps. An admin also consents once to DeviceManagementApps.ReadWrite.All and Group.Read.All for Microsoft Graph Command Line Tools, or for your own app registration.

## Known limits
- **The Intune upload is still being tested against real tenants.** It has been checked against a simulated Graph service. Try it in a test tenant or assign to a pilot group first, and please [open an issue](https://github.com/PresWiFi/PackPilot/issues) if something goes wrong. Building, testing and the deployment kit don't depend on it.
- A Sandbox pass is strong evidence, not a guarantee. Pilot before a broad rollout.
